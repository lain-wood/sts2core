**顺序为什么不能倒**（阶段 3 之前踩过）：改好的目标函数评不到一条不在候选集里的线。
后悔 = 到边界最优 − 候选集里最好的那条，而到边界最优**不在候选集**时这个差必然 > 0
⇒ 「后悔>0」最低只能降到 `miss_c`（今天 6/53，实际 12/53 ⇒ **6 个起点还归深度和目标函数管**，
预算那一路已经量过、买不到）。

**四条别踩的**：

* **阶段 2 的判据是「双重确定」，不是「单孩子」**（已落地）：`chance_children`
  返回单个 `p = 1.0` 的孩子 **且** 每只活敌人的 `step::allowed_next` 是单元素集合。
  只看单孩子的话，带随机分支的敌人会被误判成确定 —— `plan_audit` 自己量的：
  **24 个起点牌序整堆已知、但敌人要掷骰**（2026-09-06 重量，69 条语料；上一轮 14 个）。
* **`Plan::deep_score` / `Plan::window_score` 那条 P4 红线**：目标函数往防守偏会让
  推演变成"只挡不打"（`survive_first` 当跨回合策略时 P4 当场 52/8320）。
  动目标函数**必须同时看 P4**。
* **先找一条不写实现就能量到上界的路**（阶段 3.5 现学的）：一个只让**同一个效果
  更便宜**的改动，它的上界就是那个效果本身，通常一条 `--set` 就量得到。
  3.5 靠这条省掉了一天实现 + 一天九条验收。
* **读数 3 判不了"目标函数对不对"**（阶段 4 现学的）：它量的是「浅搜索离深搜索
  差多少」，前提是两边同一个目标函数。换目标函数的改动只能由 **P5 + P4** 判。
  阶段 4 那一栏的中立列两边**逐字相同**，不是没测出来，是**结构上测不了**。

`cand_score` 还是 `score::leaf`（带 `win = 100000`），而窄根上的深层尺子已经是

### 2026-09-05 新开的一栏：**引擎牌在跨回合搜索里评不到**

第 2 幕 Boss 无厌沙虫那场仗把这条从"已知拒绝计价"变成了一个**可修的数**：
`bin/bestline`（束搜索上界）在同一批 64 个种子上 **64/64 赢**，
而默认 D=2 **13/64**。差出来的那一截主要是**引擎牌** ——
束搜索的线里有 添柴+ / 无惧疼痛 / 恶魔形态+ / 恶魔之焰+，

（每回合给格挡的 · 会衰减的 · 触发式的）。

同一个台子上量到的两条，**都不是参数值本身**：

* `leaf=rollout:16:24,k=16,power-reserve=4` 把它抬到 **18/64（平均 7.0 血）**
* **`k=16` 单独加是负收益**（24 种子那轮 1 -> 0），配上推演叶子才是正的。
  **候选开宽只有在评估器分得开它们的时候才有用** —— 这是"筛子和尺子必须是
  同一把"的又一个形状，和阶段 3 学到的是同一件事。

**没有改默认**：这是一场仗上的读数，而 `Leaf::Rollout` 当默认的代价
（单次可重复性 87% -> 71%）是全语料量过的。要动默认得先有一条
「什么时候切到推演叶子」的判据 —— 那条判据本身还没有。

### 生成类牌的估值偏高（2026-08-22 玩家提出）

`solve_turn` 评估添柴 / 地狱之刃这类**生成**牌时，评的是它自己从 `GEN_POOL`
掷出来的那几张。两个问题叠在一起：

* 内核的随机流**故意**和游戏不一致（不变量 4）—— 生成的牌必然对不上，这条修不掉
* `GEN_POOL` 是真实池子与**已实现**的交集，缺的那些恰恰是机制最怪、单回合最不好用
  的那批 ⇒ **池子系统性偏好**，内核倾向于**高估**生成的收益

已做的是 A（`solve --live` 把生成的牌逐行标出来 + 单独警告）。
**没做的是 B**：让搜索里生成出来的牌落成不可打出的未知牌，把添柴+ 的估值压回
"消耗手牌 + 拿 N 张不确定的牌"。

B 要动搜索行为，所以**做之前先量**：拿现有语料跑一次对照，看 B 把添柴+ 的出场率
和 L2 验收的五个分类各改了多少。改完照例跑五项 + 突变。
判据参照药水那条老规矩：**价值算不出来就拒绝算，别给一个自信的数**。

**加钩子的规矩**：**每个钩子都要连着它的消费者一起加** —— 没有消费者的空钩子是
本仓库明令不要的东西。要加之前先去 [源码] 确认它是不是根本不需要钩子

### 进阶：认不出来的那批数值

`tools/dump_ascension.py` 按 **(种类, 低进阶值)** 去认内核的 op —— 低进阶值就是
内核今天写着的那个数。认不准（多个候选 / 判不出种类 / 内核里找不到那个值）的

手填的家是 `data/ascension_overrides.json`（今天 6 条：遗忘之物 1 · 碾碎爪 3 · 瀑布巨兽 2）。

  该进 `ASC_HP` 那一路而不是 `ASC_OPS`

## 切片里【故意】没做的（别当 bug 修）

- **没有任何牌自带保留(retain) / 固有(innate)** —— 规则本身接上了
  （`end_turn_impl` 跳过带 `F_RETAIN` 的牌、`begin_combat` 把固有挪到牌堆顶），
  但今天唯一的来源是**附魔**（王室认证）。有牌自带这两个关键字时，
  要确认 `CardDef` 那一侧也能给出 flag
- 多阶段、天罚这类每 N 回合钩子
- **雾菇的复活**：第 15 层实测利齿之眼被打死后下回合满血、状态原样回来。
  是雾菇重新召唤、还是它自己的 `ILLUSION_POWER`，**没分辨出来** ——
  按规矩欠定就留空，不挑一组自洽的解写进表。后果是内核**低估**雾菇。
- **部分药水故意不建**，各自欠什么机制列在 `ops.rs::POTIONS` 表头
- 烙印的力量是立即结算的，真实游戏是选完牌之后
- 焚烧那类"对所有敌人造成 N 点伤害 M 次"：内核是**打完一个敌人的 M 下再打下一个**,
  真实游戏可能是轮流打。只有中途状态变化（敌人死亡）时才有差别
- `targeted` 那一列是**从卡面文本推的**，权威卡表里没有 target_type 字段。
  判错了 `legal_actions` 会生成不该有的动作，实战第一次打出来就会暴露
- **回合内限时的能力**（狂怒"这个回合内每打出一张攻击牌…"）：需要 `TurnEnd` 时
  清掉的临时 power，`TempStrength` 是这一类的特例，还没推广
- 只有战斗层，没有地图 / 整局层
