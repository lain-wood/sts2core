# 实战驱动手册

用 MCP 驱动一局《杀戮尖塔 2》时怎么调工具、怎么读它们的输出、哪些地方够不到。
入口和三条决策线的分工在工作台的 [`../../CLAUDE.md`](../../CLAUDE.md)；
碰到具体某只敌人时读 [enemies.md](enemies.md)。

## 开一局

游戏通常没在跑。先启动，等 mod 的 HTTP 端点应答，再调任何 `sts2` 工具：

```bash
powershell -c "Start-Process 'steam://rungameid/2868840'"
```

轮询 `http://localhost:15526/api/v1/singleplayer?format=json` 直到它应答，
然后 `get_game_state`、`menu_select("continue")` 续上存档。

带 mod 的存档在独立的 `modded\` 存档树里，**碰不到原版档案**。重启游戏会从上一层的
自动存档续，打到一半的战斗会从头重打。

## 局内出牌：问 L2 求解器

**一条固定命令，无参数**（命令字符串一变就要重新过一次权限确认）：

```bash
& "D:\game mod\sts2core\.venv\Scripts\python.exe" "D:\game mod\sts2core\tools\solve_now.py"
```

它读当前局面，输出**这一回合逐张出牌的顺序和目标 `entity_id`**、挨完敌人这一手之后
剩多少血，以及三个目标函数的对照（三个一致 ⇒ 结论不依赖权重）。

出牌用 `combat_play_card`。**正在录 trace 时不要混用**，见下面「录制」。

### 怎么读它的输出

* **每打出一张牌就重跑一次。** `entity_id` 每帧重新编号，抽牌之后局面也变了。
* **它只看这一回合。** "留着这张牌下回合用"这类判断仍然归你。
* **它结构性地低估伤害**：打掉的血要靠"少挨几回合打"兑现，而单回合看不到那几个
  回合。存活优先和竞速两个目标函数分歧时，那一手就是真的在权衡。
* **先看威胁那一行是哪种口径。** 认得出敌人这一手时，它拿面板基础值现算，于是
  「我这一手会改敌人打多少」（凌虐减力量 / 上虚弱 / 巨像减半 / 转身 / 吃污染）
  才算得进去；认不出就退回冻住的意图标签，那时这些一概是空操作。
* **`complete` 那一列**说这个回合有没有搜完。没搜完的行是启发式排名，不是解。
* **线里的牌分三种，可信度不同**：手上真有的 > 抽到的（牌是真的，顺序不可知）
  > **生成的**（添柴那类造出来的，牌组里根本没这张）。看到"内核生成的牌"那一行，
  后面几步就别照着打：先把生成那张打出去，看游戏真给了什么，再重跑。
* **它会点名它看不见的东西**：不认识的手牌、没建模的遗物（连同卡在哪一起报）。
  那几行不是装饰。
* **判死时它会多搜一条"药水随便喝"的救命线**。逐瓶定价答不了"两瓶一起喝能不能
  不死"，而那正是 Boss 战最常见的活法。
* **游戏开着选牌界面（`pending`）时它拒绝作答。** 先把选牌做完再问。

### D=2 那条线是**被测对象，不是驾驶员**

输出里并排报一条跨回合 planner（D=2）的线。配对实测它平均比单回合好
**+4.2 血/场**（2026-09-19），但**同一个局面只换随机种子，约 29% 的回合它会换建议**
（221/312 不变）。实战一个回合只发生一次，要的是单次可重复性，
所以**驾驶只用单回合线**。两条线不一致时当分歧样本读，自己判断。

它系统性低估的一类：**每回合给格挡的能力**（绯红披风那种）和**触发式的**
（撕裂 / 黑暗之拥 / 凶恶）在叶评估里不计价，放血流那套的估值因此偏低。
逐条见 [design-l2.md](design-l2.md) 的「跨回合搜索」。

## 构筑决策：`sts2-advisor`（L3）

它答的问题是「**这副牌组走完这一幕会不会死**」：同一副牌组、同一条路线、同一批随机，
基准和每个候选各走 256 条链。

| 工具 | 什么时候用 |
|---|---|
| `snapshot_deck` | **每次走到地图屏时调一次。** 它顺带记下「这是哪一幕 / Boss 是谁」，这两样**只有地图屏上有**，而后面每个决策都要用。它还会报内核认不认识你这几张牌 / 遗物 / 药水（**一次推演都不跑，瞬间**） |
| `inspect_fight` | 战斗里：把**这一场从开局重打** 256 次，报死亡率和血量分布。内核不认识的敌人会当场拒绝作答。**它不是局内建议**，局内出牌问 `solve_now.py` |
| `boss_requirement` | **进入一幕时**：拿现在这副牌组打**那一只**（地图上写着的）Boss 256 次 |
| `inspect_deck` | 任何决策之前：不带候选的整幕评估，报走完这一幕死多少次、死在哪一间、漏掉几场 |
| `advise_card_reward` | 卡牌奖励屏（基准 = 跳过） |
| `advise_removal` | 商店，花钱之前 |
| `advise_upgrade` | 篝火，选打铁目标 |
| `advise_elite` | 地图分叉有精英时：**两条路线**的配对比较，报的仍然是 HP 代价不是遗物价值 |

四个 `advise_*` 都有一个可选的 `rooms`（`M` 杂兵 / `E` 精英 / `B` Boss / `R` 休息）。
**不给就按地图上还剩几间截一条默认路线**，而那条默认路线是一个 `[判断]`
（8 杂兵 + 1 精英 + 3 休息 + Boss），报告最上面会印出来它是怎么来的。

### 怎么读它的数

* **Δ死亡为负 = 做。** 那一列在最前面，因为它是判决量。血量差只在**两边都活下来**
  的样本上算（死掉那一侧的终点血量是 0，平均进去就是把老毛病换个地方犯）。
* **「救回 / 反送命」那两个数比 Δ死亡更直接**：它们是逐样本配对的，
  即同一条随机轨迹上，基准死了而候选活了几次。
* **「没有信号」那一行要当真。** 两边结局逐样本相同时，Δ 全是 0，而那不是结论。
  这时看后面那句次要读数：**两边都死的链里谁走得更深** / 两边都死的仗里
  **谁把敌人打得更残**。
* **覆盖率和结论并排印**：「这一幕内核开得出几场」和「平均每条链漏掉几场」。
  漏掉的那几场没挨打，所以**每个死亡率都是乐观的**。
* **报告末尾那几行不是装饰**：它自己算出来的已知偏差（几张能力牌 ⇒ 低估 ·
  几瓶药水 ⇒ 低估 · 构造器缺口 · A8 以上）和「没打成的那几场」逐条列着。
* **绝对水平不可信，成对的差值才可信。** 用来比较，不要用来打分。

### 它做不到什么（依赖它之前先看）

1. **覆盖率不是 100%。** 抽到内核开不出的那一场就**跳过并计数**，死亡率因此系统性
   偏乐观。现数看 [acceptance.md](acceptance.md) 的「当前基线」：第 1、2 幕全开得出，
   第 3 幕只差女王（Boss）。A10 最后一幕是双 Boss，3 只里抽 2 只，女王出现的概率是 2/3；
   而内核里现有的「蜂后」是一条 `[wiki]` 档的**错**定义，打女王时 D=2 那条线和
   按敌人定义算的威胁都别信。补法是往内核里补敌人。
   **新补的敌人大多是 `[源码]` 档、一场实录都没有**，逐只见 [enemies.md](enemies.md)。
2. **它报的是「这副牌组在我们这套策略手里」的成色。** 回溯检验量到**每场比玩家多掉
   约 6.7 血**，一幕几场就是几倍。而策略对**引擎牌**（每回合给格挡的 / 会衰减的 /
   触发式的）系统性低估，所以**带引擎的构筑（放血流、消耗流）它给的分偏低**，
   那一条会印在报告里。
3. **第 1 幕认不出是哪一幕**，除非先过一次地图屏：`run.act` 只有 1/2/3，
   而 Overgrowth 和 Underdocks 同序号。缓存换幕或新开一局就作废，
   **认不出来它会拒绝作答**，不会猜。
4. **局外一律不建**：卡牌奖励池「以后还能拿到什么」· 事件 · 商店 · 金币 ·
   路上捡的遗物 · **路线**。精英掉的遗物也不建，`advise_elite` 报的是血价。
5. **内核不认识的牌 / 遗物 / 药水会被点名**（"不认识"和"没效果"是两件事）。
   牌照放但打不出来 ⇒ 那副牌组在推演里**比真的弱**；遗物和药水直接不生效。
   **看到点名先想一下它会把结论推向哪一边。**
6. **推演一瓶药水都不喝**（低估）· **进阶 A8 以上整张表是 `[源码]` 档**
   （全部实录是 A1–A3，方向不定）。
7. **`node_budget` 参数已经没有对应物**：L2 的单回合搜索是穷尽的，传了它会说一句然后忽略。

## MCP 够不到的操作（实测撞到的）

* **佩尔之翼的「献祭」点不到。** 卡牌奖励界面上「跳过」和「献祭给佩尔」是两个按钮，
  而 `ExecuteSkipCardReward` 写死了 `altButtons[0].ForceClick()`，只能点到跳过。
  带着佩尔之翼时，不想要的卡牌奖励**要请用户手动点献祭**（2026-08-17 实测：跳过之后
  计数器仍是 `[0]`）。根治要改 `STS2MCP/McpMod.Actions.cs` 并重新构建。

* **药水槽号在喝掉一瓶之后会重排。** 2026-08-22 实测：三瓶时喝掉槽 0，剩下两瓶
  报成 `药[1]`/`药[2]`，照上一屏的槽号传 `potion 1` 喝错了瓶子。
  和 `entity_id` 每帧重编号是同一类坑：**每次用药水前重读一次当前槽号。**

* **「从牌堆里挑几张」的选牌屏：点得到，但"选中"这件事不可观测。**
  `select_card` 打过去，动作**多半真的生效了**（`NCombatPileCardSelectScreen`
  继承自 `NCardGridSelectionScreen`，类型判断本来就匹配），但 mod 不报这类屏的
  选中状态（`selected_cards` 只给手牌选择屏构造），于是「状态没变 ⇒ 被拒」这条判据
  给出**假阴性**。

  录制器因此**读 mod 自己回的 `status`**（`{"status":"ok"}` / `{"status":"error",…}`）
  来判成败，观测差分只做兜底。**这个豁免只给 `select_card`**：出牌那条差分判据必须
  留着（2026-08-17 漏了 `--target` 被游戏拒收、而 mod 没回 error，正是靠它抓的）。

  根治是给 `BuildCardSelectState` 加一个纯读取补丁，见 [sts2mcp-patches.md](sts2mcp-patches.md)。

## 录制对拍 trace

内核的验证靠实录 trace。录制**不走 MCP**，走固定命令 + 固定路径的配置文件
（每出一张牌换一次命令字符串，就要过一次权限确认）：

```bash
# 驱动式：我出牌，动作是已知的。动作全写进 traces/_plan.txt
& "D:\game mod\sts2core\.venv\Scripts\python.exe" "D:\game mod\sts2core\tools\record_trace.py" --plan

# 被动式：玩家出牌，动作是反推的。配置走 traces/_watch.txt
& "D:\game mod\sts2core\.venv\Scripts\python.exe" "D:\game mod\sts2core\tools\watch_trace.py"
```

**用驱动式录制器出牌时不要再用 `combat_play_card`**：两条路径混用，录制器会发现
"有动作绕过了录制器"，那一帧只能作废重录。读状态用哪个都行。

计划文件每行一个步骤，语法和子命令一样（`trace <路径>` / `init` /
`play 0 --target X` / `end` / `potion 0` / `note ...` / `finish`）。跑完会**自动把
动作行全注释掉**，所以重复执行是空操作；任何一步失败都会停下，报出是第几步、
原文和原因。

被动录制器**写进 trace 的每个动作都带 `inferred: true`**，反推不出来的写
`kind="unknown"`：**一个自信地填错的动作比一个诚实的 unknown 更难查。**
观测是不可再生的证据、动作只是推断，所以反推规则改进之后不用重打一场，
跑 `tools/reinfer_trace.py` 就行。两种语料证据档次不同：`passive_*.json` 不进默认 glob。

录制强度是用户定的：**精英 / Boss 必录，杂兵抽查**（抽查的判据是有没有内核没见过的
牌 / 敌人 / 药水 / 遗物）。trace 的格式见 [trace-format.md](trace-format.md)。
